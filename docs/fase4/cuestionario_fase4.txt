1. PROPÓSITO DEL INSTRUMENTO
--------------------------------------------------------------------------------

Este cuestionario recoge la evaluación de un consultor anónimo sobre el dashboard
NYC Mobility Pulse. No busca calificar a la persona ni recoger su identidad: busca
medir si el tablero es claro, usable, pertinente y útil para responder a la pregunta
analítica del proyecto:

    ¿Cuándo, dónde y a qué costo se mueve la ciudad de Nueva York?

El instrumento combina cinco técnicas sugeridas en la Fase 4:

  a) Perfil del consultor, para cruzar los resultados con el nivel de experiencia.
  b) Tareas de uso, para medir desempeño real y no solo percepción.
  c) Escalas Likert de 1 a 5, para usabilidad, comprensión, KPIs, estética,
     interactividad e impacto.
  d) Escala SUS (System Usability Scale), para obtener un índice estandarizado.
  e) Preguntas abiertas, para recoger comentarios y propuestas.

El cuestionario NO incluye resultados: se aplica primero y se analiza después.

3.1 Crear el formulario

  - Descripción: copiar el bloque "TEXTO DE PORTADA" de la sección 4.1.

3.2 Configuración (ícono de engranaje)
  - "Recopilar correos electrónicos": NO.
  - "Limitar a 1 respuesta": NO (exigiría iniciar sesión y rompería el anonimato).
  - "Mezclar orden de preguntas": NO (las escalas deben conservar su orden).
  - "Mostrar barra de progreso": SÍ.
  - "Modo cuestionario": NO (no hay respuestas correctas que calificar en vivo).

3.3 Secciones
  - Crear una sección por cada bloque S0 a S11, con el nombre exacto del archivo.
  - En cada sección, agregar la descripción corta que se indica.

3.4 Tipos de pregunta
  - "Opción múltiple" para el perfil (una sola respuesta).
  - "Respuesta corta" para las tareas T1 a T4.
  - "Escala lineal" (1 a 5) para cada ítem de S3 a S9 y para T05. No usar
    cuadrículas: Google Forms no permite prellenarlas y complican la exportación.
  - "Opción múltiple" para T06 (tiempo dedicado a las tareas).
  - "Párrafo" para las preguntas abiertas.

3.5 Lógica de la sección S0
  - Pregunta Q00 "¿Acepta participar?" → Opción múltiple: "Sí, acepto" / "No acepto".
  - Menú de tres puntos → "Ir a la sección según la respuesta".
  - "No acepto" → sección S11 (Cierre).
  - "Sí, acepto" → sección S1 (Perfil).

3.6 Obligatoriedad
  - S0, S1, S2 (T1 a T4, T05 y T06) y S3 a S9: obligatorias.
  - S10 (abiertas): opcionales, salvo O2, que conviene marcar como obligatoria.
  - No marcar como obligatoria la pregunta de comentarios finales.

3.7 Antes de publicar
  - Abrir el formulario en el teléfono y en la computadora.
  - Verificar que el enlace del dashboard abre en una pestaña nueva.
  - Enviar una respuesta de prueba y borrarla (Respuestas → menú → Borrar todo).

3.8 Modo prellenado desde el sitio (opcional)
  El dashboard incluye una encuesta asistida que se abre con el parámetro
  ?evaluar=1 y, al terminar, abre este formulario con las respuestas ya
  cargadas. Para conectarlo:

    a) Crear el formulario con este documento y publicarlo.
    b) Completar las secciones que falten con docs/fase4/completar_formulario.gs
       (Apps Script) y volver a publicar.
    c) En el proyecto del dashboard, ejecutar "npm run form:entries": el script
       lee el formulario publicado y escribe src/lib/form-entries.json con el ID
       y los entry de cada pregunta. No hay que copiarlos a mano.
    d) Abrir https://srmeme64.github.io/nyc-mobility-pulse/?evaluar=1 y probar
       una respuesta completa.

  Requisitos para que el prellenado funcione:
    - Una pregunta por ítem (escala lineal), nunca cuadrículas.
    - Las opciones deben escribirse exactamente como aquí: el prellenado
      compara el texto de la opción.
    - La pregunta P13 recibe el detalle de las opciones "Otra" elegidas en el
      sitio (género, formación u ocupación).
